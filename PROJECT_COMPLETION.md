# PROJECT_COMPLETION.md — Tilliworld Shop

Обновлено: 2026-10-16. Статус: **код завершён и проверен локально; интеграция с реальным проектом Supabase не проверена** (см. «Ограничения»).

## Назначение и архитектура
Каталог предметов и заявки для Minecraft-сервера Tilliworld (1.16.5). Оплаты, корзины и выдачи предметов нет, это сознательное решение ТЗ.

- Стек: React 19 + Vite 8 + Tailwind CSS v4 + React Router 7 + lucide-react + supabase-js 2.
- `src/pages` публичные страницы, `src/pages/admin` админка, `src/layouts` раскладки (`AdminLayout` содержит вход и проверку роли).
- `src/services/shop.js` единственный слой доступа к данным; `src/lib` чистая логика (`images`, `ids`, `orderErrors`, `storage`); `src/hooks` (`useAsync`, `useAuth`); `src/components` UI (`Dialog`, `Toast`, `ImageUploader`, `OrderForm`...).
- Безопасность в базе: `supabase/migrations/001_init.sql` (таблицы, RLS, `create_order`), `002_storage_and_hardening.sql` (Storage, заявки меняются только по статусу, https для `image_url`). Администратор = `app_metadata.role = 'admin'`.
- Без `.env` работает демо-режим: тестовые предметы, заявки не сохраняются, админка показывает инструкцию.

- Регистрация и вход в браузере против настоящей базы; кнопки выдачи в `Orders.jsx` в браузере не нажимались (проверены линтом, сборкой и SQL-функцией).
- Интеграция с Minecraft: не проверялась и не реализована для выдачи; плагин только подтверждает ник, на реальном сервере и Aternos не запускался.

### Ручные действия
1. Применить миграцию 012 в Supabase (SQL Editor) после 011.
2. Ограниченным администраторам, которые обрабатывают заказы и товары, добавить `"shop"` в `app_metadata.permissions` и перелогиниться (JWT обновится).
3. Проверить в Supabase Dashboard, что у таблиц `player_*`, `economy_*`, `wheel_*` включён RLS (в миграциях включён).
4. На сервере Minecraft: выдавать предметы и привилегии вручную, затем нажимать «Выдано». Автовыдача потребует отдельного серверного обработчика.
